Section 01

Overview

Direct Connector is a cross-platform desktop app built with Wails v2 (Go backend + WebView frontend). It ships two independent modes — SSH reverse tunnel and serverless WebRTC P2P — plus an embedded TURN relay server, all wired together through a single Go struct whose exported methods become async TypeScript bindings via the Wails bridge.

Frontend Vue 3 + TypeScript
──── Wails JS bridge ────
Go Backend app-wails/app.go · App{}
internal/tunnel SSH subprocess mgr
internal/p2p WebRTC session
internal/relay Embedded TURN
internal/sshsetup Key installer
system ssh binary or wsl.exe ssh
pion/webrtc v3 DTLS + ICE + DataChannel
pion/turn v2 RFC 5766 TURN server
Shared by both modules
internal/config
internal/keygen

The shared packages (config, keygen) are structurally mirrored between the two Go modules but are never imported across module boundaries. All user configuration flows through internal/config; Ed25519 keypairs through internal/keygen.

Section 02

Two Go Modules

The repository contains two independent Go modules at separate paths. This split preserves a clean headless/Docker build that carries zero GUI dependencies while the Wails module can freely import Wails runtime packages.

Module Path Module name Purpose
Wails GUI app-wails/go.mod direct-connector Desktop app — Wails v2 + WebView; exports Go methods as async TypeScript bindings via the Wails bridge.
Fyne / CLI / Docker app/go.mod mqtt-tunnel Native-widget Fyne GUI, headless CLI binary (nofyne build tag), and Docker image with zero GUI dependencies.

Module boundary rules

  • Never import across modules. direct-connector and mqtt-tunnel are fully separate Go dependency graphs.
  • Mirror shared logic. Edits to internal/config, internal/keygen, internal/tunnel, or internal/p2p must be applied in both app-wails/internal/ and app/internal/.
  • Wails-only packages. internal/relay and internal/sshsetup live only in the Wails module — they have no counterpart in app/.

Build tags (app/ only)

The Fyne module uses build tags to produce two binary variants from the same source tree. The default build (no tag) links the full Fyne GUI. Adding nofyne swaps main.go for main_nofyne.go and produces a static binary with no OpenGL or X11 dependency — suitable for Docker.

TagEntry pointUse case
(default)main.go, ssh_tab.go, p2p_tab.goNative Fyne desktop GUI
nofynemain_nofyne.goHeadless CLI / Docker (CGO_ENABLED=0, static)
Section 03

internal/config

Manages reading and writing the single JSON configuration file. The file is never created until the user first saves settings; if absent, safe defaults are returned silently. Parse errors are printed to stderr and the defaults are used — the app never crashes due to a corrupted config file.

Version migration

The Version field is reserved for future schema migrations. Currently only one migration is implemented: if an existing config has an empty IPVersion field but the legacy IPv6: true boolean is set, the load path automatically promotes it to IPVersion = "6". Future migrations follow the same pattern — check cfg.Version and rewrite fields before returning the config to callers.

Section 04

internal/keygen

Manages the app-owned Ed25519 SSH keypair. Keys are stored alongside the config file under the MQTTTunnelManager app directory.

File paths

FilePathPermissions
Private key <AppDir>/id_ed25519 0600 — OpenSSH PEM format, no passphrase
Public key <AppDir>/id_ed25519.pub 0644 — single authorized_keys line

Key operations

🔑

GenerateAppKey()

Creates a new Ed25519 keypair using crypto/rand. Overwrites any existing files at the key paths. The app directory is created with 0700 if it doesn't exist.

✓

AppKeyExists()

Idempotency guard — returns true if the private key file is present on disk. app.go calls this before generating to avoid overwriting a working keypair.

📋

LoadAppPublicKey()

Returns the public key as a trimmed authorized_keys line, ready to be copy-pasted into the server's ~/.ssh/authorized_keys.

📁

AppPrivateKeyPath()

Returns the OS-appropriate absolute path to the private key file. Exposed to the frontend so the user can also reference the key manually in an SSH config.

Section 05

internal/tunnel

The tunnel package wraps the system ssh binary in a managed subprocess that automatically reconnects on failure. A sync.Mutex guards all mutable fields; callbacks are invoked from a background goroutine so callers must dispatch to the UI thread if needed.

Manager lifecycle — state machine

Disconnected
Start(cfg)
Connecting…
2 s timer fires
Connected ✓
ssh exits
Reconnecting

After 5 s backoff the loop returns to Connecting. Calling Stop() from any state transitions directly to Disconnected.

BuildSSHArgs

BuildSSHArgs(cfg Config) constructs the full argument slice passed to the ssh binary and validates all port numbers before returning. Key flags applied:

  • -N — no remote commands, port-forwarding only
  • -o ServerAliveInterval=30 — keepalive every 30 s
  • -o ServerAliveCountMax=3 — disconnect after 3 missed keepalives
  • -o ExitOnForwardFailure=yes — exit if port binding fails (prevents silent failures)
  • -o StrictHostKeyChecking=accept-new — auto-accept new hosts; reject changed keys
  • -R port:localhost:port or -L port:localhost:port for each forwarded port

Reconnect backoff

A fixed 5-second waitOrCancel delay is applied between reconnect attempts. If the SSH process exits in under 3 seconds, the monitor loop emits a set of diagnostic hints to the log (wrong username, bad key, port mismatch, known_hosts conflict) rather than silently looping.

Windows: WSL SSH

When UseWSLSsh is set, the manager substitutes the binary wsl.exe and prepends ssh to the argument list. This causes SSH to execute inside the WSL network namespace — the same context where Docker and MQTT brokers typically run on Windows. hideWindow(cmd) suppresses the console popup on Windows (a no-op on macOS/Linux).

Section 06

internal/p2p

Implements a serverless peer-to-peer tunnel using WebRTC DataChannels (pion/webrtc v3). After a one-time out-of-band SDP copy-paste, all data flows directly between the two machines over encrypted DTLS 1.2. No relay server is involved unless symmetric NAT prevents direct ICE connectivity.

Session roles

📤

Consumer (Initiator)

Calls GenerateOffer(ctx, ports). Opens local TCP listeners on the specified ports. Each accepted TCP connection creates a new DataChannel to the Provider.

📥

Provider (Responder)

Calls AcceptOfferAndGenerateAnswer(ctx, offerSDP). For each DataChannel whose label is a port number, bridges the channel to localhost:<port> on the Provider machine.

SDP encode / decode

SDP blobs are serialised as JSON, then base64-encoded to produce a single-line opaque string. This format is safe to copy through any channel (chat, email, QR code) without escaping. The receiving side calls decodeSDP(raw) which base64-decodes then JSON-parses back into a webrtc.SessionDescription.

ICE gathering

The session uses five public STUN servers (Google × 2, Cloudflare, Nextcloud) for NAT discovery — UDP and TCP variants. STUN is contacted once per side at startup to discover the machine's public IP:port; no tunnel traffic ever passes through a STUN server.

After ICE gathering the session waits up to the configured GatherTimeoutSecs (default 30 s). If the timer fires, gathered candidates so far are used — the connection attempt continues with partial candidates.

TCP mux option

When TCPMuxPort is non-zero, a pionice.NewTCPMuxDefault listener is bound on that port before creating the PeerConnection. This exposes a fixed TCP port for ICE-TCP candidates — useful when the port should be predictable for firewall rules. Port 443 is the recommended value; TCP traffic to 443 is indistinguishable from HTTPS to most network appliances.

TURN / STUN configuration

User-provided TURN servers are appended to the ICE server list after the default STUN entries. Each TURNServer carries a URL (turn: or turns: scheme), username, and credential. TURN is only needed when both peers are behind symmetric NAT or CGNAT.

ICE timeouts

ParameterValueRationale
disconnectedTimeout5 sDetect dead path quickly
failedTimeout25 sAllow time to try all candidate pairs
keepAliveInterval2 sLow overhead on long-idle tunnels

DataChannel bridge

Once a DataChannel opens on the Provider side, dc.Detach() returns a raw io.ReadWriteCloser. The package then calls bridge(raw, localConn) which runs two io.Copy goroutines in opposite directions, each protected by a sync.Once to prevent double-close races.

Section 07

internal/relay

Wraps pion/turn v2 to provide an embedded TURN relay server. This allows the P2P mode to work even when both peers are behind symmetric NAT or CGNAT — the relay forwards UDP packets between the peers without seeing the encrypted payload.

🌐

Public IP discovery

On Start(port), the relay dials stun.l.google.com:19302 via UDP to discover the machine's public IP. Falls back to a UDP-dial heuristic if STUN is unreachable.

🔐

HMAC-SHA1 credentials

Generates a random 32-character hex secret at startup. Credentials are time-limited: the username encodes a Unix timestamp and the password is HMAC-SHA1(secret, username) per RFC 5766 §10.2.

📡

Dual transport

The relay listens on UDP (primary, per RFC 5766) and attempts to bind a TCP listener on the same port. The TCP address is exposed as TURNTCPAddr — empty if the TCP bind failed.

🔄

Credential refresh

Credentials() generates a fresh username/password pair on every call using the current Unix timestamp. Clients should re-fetch credentials before each session rather than caching them long-term.

Lifecycle

relay.New(onLog) constructs an idle instance. Start(port) discovers the public IP, opens the UDP packet conn, optionally opens the TCP listener, and starts the pion/turn server. The call is idempotent — if the server is already running it returns an error. Stop() gracefully shuts down the server and closes both listeners; safe to call when not running.

The relay logs all significant events via the OnLog callback, which app.go wraps to prepend a timestamp and emit as a relay:log Wails event.

Section 08

internal/sshsetup

Provides a one-click "install key" workflow that dials the SSH server via pure-Go golang.org/x/crypto/ssh, interactively confirms the host fingerprint, authenticates with a password, and appends the app public key to ~/.ssh/authorized_keys on the server. Only lives in app-wails/ — the Fyne/CLI module has no equivalent.

Interactive flow

1

Key generation

app.go calls keygen.GenerateAppKey() if no app key exists, then loads the public key string for injection.

2

Dial & fingerprint prompt

Installer.Run(ctx, Config) dials the server. The host key callback emits a setup:prompt { kind: "fingerprint", … } Wails event and blocks on a reply channel.

3

User confirmation

The frontend shows a modal; the user clicks Accept/Reject. The frontend calls App.SSHSetupReply("yes") or App.SSHSetupReply("no") to unblock the goroutine.

4

Password prompt

If fingerprint accepted, the installer emits setup:prompt { kind: "password", … } and blocks again. The user enters their password in the frontend; SSHSetupReply(password) unblocks.

5

Key installation (idempotent)

Opens an SSH session, checks for the public key in ~/.ssh/authorized_keys using a server-side grep -qxF, and appends it only if not already present.

6

Completion event

Emits setup:done { ok: true, message: "Public key installed successfully." }. On any error the ok field is false and message contains the error string.

Events emitted

EventPayload
setup:logTimestamped log string (progress messages)
setup:prompt{ kind: "fingerprint"|"password", message, fingerprint }
setup:done{ ok: bool, message: string }
Section 09

app-wails/app.go

App is the single exported struct. All of its exported methods become async TypeScript functions callable from the Vue frontend via the Wails JS bridge. Frontend-facing types are defined in app.go — not in internal/ — so Wails generates clean camelCase TypeScript interfaces.

Startup hook

startup(ctx context.Context) is the Wails lifecycle hook called once the WebView window is ready. It:

  • Stores the Wails context.Context (required by runtime.EventsEmit)
  • Constructs the relay.Relay with a log callback that prepends a timestamp
  • Constructs the tunnel.Manager with OnStatus and OnLog callbacks
  • Calls setupTray() to register the system tray icon and menu

Event emission pattern

All backend → frontend messages use runtime.EventsEmit(ctx, eventName, payload). Event names follow a subsystem:verb convention:

EventPayload typeEmitted by
tunnel:statusstringtunnel.Manager.OnStatus
tunnel:logstringtunnel.Manager.OnLog
p2p:statusstringp2p.P2PSession.OnStatus
p2p:logstringp2p.P2PSession.OnLog
relay:logstringrelay.Relay.OnLog
setup:promptSetupPromptsshsetup.Installer prompt callback
setup:logstringsshsetup.Installer log callback
setup:doneSetupResultpost-install goroutine in SSHSetupStart

Mutex guarding shared state

A single sync.Mutex mu on App protects all mutable fields: p2pSess, p2pCancel, p2pConfig, sshInstaller, setupCancelFunc, and setupBusy. The pattern is always lock → read/write → unlock (never defer unlock around blocking calls).

Shutdown

shutdown() is registered as the Wails OnShutdown hook. It stops the tunnel, the P2P session, and the relay in sequence, then calls teardownTray() to remove the system tray icon.

Section 10

Frontend Architecture

The frontend lives at app-wails/frontend/ and is built with Vue 3 Composition API, TypeScript, and Tailwind CSS. The Wails build tool runs npm run build and embeds the resulting dist/ as the WebView content.

Component structure

🔗

SshTab.vue

SSH tunnel configuration form, start/stop controls, log output, and the <Teleport to="body"> SSH setup modal for interactive key installation. Uses v-show (not v-if) to keep the tab mounted.

🌐

P2pTab.vue

WebRTC P2P controls: Consumer offer generation, Provider answer acceptance, SDP text boxes, relay start/stop, TURN credential display, and the advanced ICE configuration panel.

✅

portValidation.ts

Shared utility that validates comma-separated port strings. Used by both SshTab and P2pTab to surface input errors before calling backend methods.

Wails JS bindings pattern

Wails generates TypeScript functions in wailsjs/go/main/App.js for every exported method on App. Components import and call them as regular async functions:

import { StartTunnel, StopTunnel, IsTunnelRunning } from '../wailsjs/go/main/App'; // Call backend method — returns Promise<string> const err = await StartTunnel(settings); if (err) console.error(err);

Event listener lifecycle

Components subscribe to backend events in onMounted and unsubscribe in onUnmounted to prevent memory leaks. The Wails runtime provides EventsOn(event, callback) and EventsOff(event):

import { EventsOn, EventsOff } from '../wailsjs/runtime/runtime'; onMounted(() => { EventsOn('tunnel:status', (msg: string) => { status.value = msg; }); EventsOn('tunnel:log', (msg: string) => { logs.value.push(msg); }); }); onUnmounted(() => { EventsOff('tunnel:status'); EventsOff('tunnel:log'); });

Dark theme alignment

Tailwind's dark theme uses bg-gray-900 as the root background, matching the Wails BackgroundColour configured in main.go. This eliminates the white flash that can appear during WebView initialisation on slower machines.

Section 14

Key Technical Decisions

WHY Wails v2 for the GUI

Wails embeds the OS-native WebView (WKWebView on macOS, WebView2 on Windows, WebKitGTK on Linux) so the binary ships without a bundled Chromium. The result is a small download (<10 MB), native OS feel, and system tray support — with no Electron-style memory overhead. The Go ↔ TypeScript binding is codegen-free: any exported method on App becomes a typed async function automatically.

WHY pion/webrtc for P2P

pion/webrtc is a pure-Go WebRTC implementation with zero CGo. It cross-compiles cleanly to all target platforms and exposes enough low-level access (setting engine, TCPMux, Detach() for raw DataChannel I/O) to implement a general-purpose TCP-over-WebRTC bridge. The DTLS 1.2 layer is provided for free as part of the WebRTC spec.

WHY System ssh binary

Invoking the system SSH binary rather than a pure-Go SSH client means the app inherits the full ecosystem: SSH agents, ~/.ssh/config, OpenSSH keepalive semantics, and any host-specific options the user has already configured. It also avoids maintaining a complex SSH client implementation. The trade-off is that the binary must be on PATH; the manager emits a helpful hint if it is not found.

WHY Two Go modules

The Fyne/CLI module must build with CGO_ENABLED=0 and the nofyne tag to produce a static binary suitable for Docker. Merging it into the Wails module would pull in Wails runtime imports that reference CGo and WebView symbols, breaking the headless build. Keeping separate modules preserves independent dependency graphs while the Makefile orchestrates both with a single make test.

ALT Port 443 as SSH default

The default SSH port is 443 instead of 22. Port 443 is universally open on firewalls and corporate proxies because it carries HTTPS. An SSH connection on 443 is indistinguishable from TLS at the packet level, allowing the tunnel to work in environments that block port 22.

ALT Embedded TURN relay

Rather than requiring users to deploy a separate TURN server, Direct Connector embeds one via pion/turn. Any machine with a public IP can become a relay with one click. HMAC-SHA1 time-limited credentials prevent anonymous use without requiring a database or user registry.
