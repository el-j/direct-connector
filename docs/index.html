Three tunnel modes

Every way to connect,
without locking you in.

Each tunnel method works independently. Use one, use all three — the app keeps your settings and reconnects automatically.

🔐

SSH Reverse Tunnel

Creates a persistent, self-healing reverse SSH tunnel to any jump host you control. Automatic reconnect with 5-second back-off. Survives sleep, network changes, and interrupted connections without any action from you.

port 443 Ed25519 keys one-click install IPv6 WSL SSH
🌐

Serverless P2P Tunnel

A 100 % serverless peer-to-peer encrypted channel using WebRTC DataChannels and ICE — the same stack your browser uses for video calls. Exchange one text blob between machines, click Connect, and you're done. Nothing touches a third-party server.

DTLS 1.2 WebRTC STUN / TURN copy-paste SDP ICE-TCP
⚡

Embedded TURN Relay

Run your own TURN relay server directly inside the app — no separate service or cloud account needed. Generates time-limited HMAC credentials automatically, supports UDP and TCP, and streams live relay logs.

pion/turn UDP + TCP HMAC credentials public IP discovery
🔑

One-click Key Installer

No need to copy keys manually or open a terminal. The app generates an app-managed Ed25519 keypair, dials your server, and installs the public key into ~/.ssh/authorized_keys — all in a guided in-app wizard with password and fingerprint prompts.

Ed25519 x/crypto/ssh fingerprint UI
🖥️

P2P connection flow

Two machines.
One text blob.
Direct channel.

The P2P tunnel uses the same NAT traversal technique browsers use for video calls — ICE + STUN. No server handles your traffic. After the initial handshake, every byte goes machine-to-machine over an encrypted DTLS 1.2 DataChannel.

1

Consumer generates an Offer

Enter the ports to expose locally, click "Generate Offer", and copy the short base64 blob.

2

Provider accepts and answers

Paste the Offer on the Provider machine, click "Accept & Generate Answer", and copy the Answer blob back.

3

Consumer connects

Paste the Answer and click "Connect". ICE negotiates a direct path — behind NAT, through firewalls, over IPv4 or IPv6.

4

Encrypted tunnel is live

All traffic flows direct. Zero bytes go through any server. The tunnel stays up until you stop it.

Technical properties

Built for correctness.

DTLS 1.2 end-to-end encryption

WebRTC mandates DTLS on every DataChannel. All P2P traffic is encrypted between the two peers — not terminated at a relay.

ICE NAT traversal

Works through most home and office routers via STUN. Optionally add TURN servers — including the built-in relay — for symmetric NAT / CGNAT.

SSH auto-reconnect

Spawns the system ssh binary and monitors it. Reconnects after 5 seconds on any disconnect, indefinitely.

Race-safe Go backend

All shared state is guarded by sync.Mutex. The full test suite runs with -race on every CI run.

No internet required for P2P

Once both peers exchange the SDP blob, no further internet access is needed. The connection is direct even on a local network.

Persistent config

Settings saved to the OS-native config directory. Keys, host, ports, and all preferences survive app restarts.

CLI & Docker

No display?
No problem.

The exact same tunnelling engine — SSH, P2P consumer/provider, and keygen — compiles to a static binary with zero CGO. Run it on a headless server, in a container, or inside a Docker Compose stack. Every flag reads from a DC_* environment variable.

The Docker image is built in two stages and runs FROM scratch — just the binary and CA certs. Final size: ~10 MB.

# SSH tunnel — environment-variable style $ docker run --rm \ -e DC_MODE=ssh \ -e DC_HOST=jump.example.com \ -e DC_PORT=443 \ -e DC_USER=admin \ -e DC_PORTS=1883,3391 \ -v dc-config:/config \ direct-connector:latest   # P2P provider (file-based SDP for compose) $ ./direct-connector-cli \ --mode p2p-provider \ --offer-in /data/offer.txt \ --answer-out /data/answer.txt   ✓ tunnel connected — forwarding 1883,3391
